AOTAutograd 联合图追踪管道

将 PyTorch 运行时自动微分引擎提前到编译时执行——用一次性追踪与分区开销， 替代每次训练迭代中成百上千次的逐算子 dispatch。

PIPELINE / 01

4步变换管道

①
Functionalization
消除副作用，确保纯函数语义
将所有 in-place 操作转为函数式等价形式：
x.add_(y) → x = torch.add(x, y)
x.copy_(y) → x = y.clone()

同时处理 RNG 函数化、token 系统和 FunctionalTensor 包装。 这是后续 autograd 正确追踪的前提。
②
Joint Tracing
前向+反向捕获为单张FX图
在 tracing 模式下调用 torch.autograd.grad()——
所有 backward ops（ConvolutionBackward0, AddBackward0...） 被拦截并记录为 FX 节点。

签名：(primals, tangents) → (fw_outs, grad_inputs)
通过 partitioner_tag 标记节点归属。
③
Min-Cut Partition
拆分为前向图+反向图
将联合图建模为流网络，找最小割：
割的一侧=前向，另一侧=反向。

关键优化：便宜操作（sin/cos/pointwise） 宁可在反向重算，不保存中间结果。
昂贵操作（matmul/conv）保存中间结果。
自动优化显存与计算的权衡。
④
FW Wrapping
包装回 eager 引擎
将编译好的前向图 + 反向图包装为
torch.autograd.Function 子类。

用户调 .backward() 时，autograd 引擎照常运行， 但每个编译区域的反向图作为"原子操作"执行， 跳过了逐 op 的 dispatch 开销。

PERFORMANCE / 03

性能收益来源

O(n) → O(1)

Dispatch 开销消除

eager 模式每个 op 走一遍 Python dispatch → C++ kernel 路径。AOTAutograd 把整段图编译为一个单元运行，dispatch 开销从线性降为常数。

Fusion

算子融合

eager 模式下 relu(w @ x + b) 是 3 次独立 kernel launch。编译后 TorchInductor 可将其融合为单个 kernel——数据无需在显存和寄存器间反复搬运。

Checkpoint

智能激活重计算

Min-cut 分区算法自动决策：便宜 op（sin/cos/pointwise）在反向重算；昂贵 op（matmul/conv）保存中间结果。大模型可用更大的 batch size。

⚠ 固定开销：~10–30μs

编译路径有固定的 wrapper 开销（runtime 状态检查、aliasing 处理、subclass 边界情况）。在极小的操作上可能是负优化——真实收益在运行完整模型时才能体现。主要热点在 jit_compile_runtime_wrappers.py。

DESIGN / 04

Tangent Mask 与 OutputType 设计

并非所有 requires_grad=True 的输出都需要 tangent——精确的 alias analysis 决定每个输出的梯度计算策略

non_alias ✓ tangent
独立输出，需要独立计算梯度。正常参与 backward。
unsafe_view_alias ✓ tangent
来自 unsafe view 操作的别名输出。虽与原 tensor 共享存储，但 view 关系不可追踪，需独立 tangent。
custom_function_view ✓ tangent
来自自定义 autograd.Function 的 view 输出。不可做 view-replay，需独立 backward tracing。
alias_of_input ✗ no tangent
输出是输入的别名，梯度已在输入的梯度中计算，无需独立 tangent。
is_input ✗ no tangent
输出就是输入本身。避免循环梯度。
alias_of_intermediate ✗ no tangent
输出的 _base 已经是图输出或中间结果，无需额外 tangent。
Token 隔离机制： 在 create_joint 调用 autograd.grad() 之前，代码保存并清空 functional_tensor_mode._tokens——确保前向和反向拥有独立的副作用 token 链。 前向 token 不会泄露到反向，反向 token 独立创建并作为 graph input 加入联合图。 这是正确处理 RNG 等有状态操作的关键。
