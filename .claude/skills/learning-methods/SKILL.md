## 各方法核心速查

### 1. 费曼学习法（4步）
**→ 详细内容：`references/01_feynman_technique.md`**

```
选择主题 → 假装教授他人 → 发现盲区回补 → 简化语言类比
关键：能用最简单的话讲清楚 = 真正理解了
```

### 2. 西蒙学习法（5步）
**→ 详细内容：`references/02_simon_method.md`**

```
锁定目标 → 知识模块化拆解 → 专注投入 → 持续反馈 → 整合巩固
理论依据：50,000信息块 × 1分钟/块 ÷ 40小时/周 ≈ 6个月
```

### 3. SQ3R阅读法（5步）
**→ 详细内容：`references/03_sq3r_method.md`**

```
Survey（浏览10%）→ Question（提问10%）→ Read（阅读50%）
→ Recite（复述20%）→ Review（复习10%）
```

### 4. 番茄学习法（循环）
**→ 详细内容：`references/04_pomodoro_technique.md`**

```
任务规划 → 25分钟专注（1番茄）→ 5分钟短休
→ 重复4次 → 15-30分钟长休 → 下一轮
```

### 5. 康奈尔笔记法（5R）
**→ 详细内容：`references/05_cornell_notes.md`**

```
Record（记录）→ Reduce（简化）→ Recite（背诵）
→ Reflect（思考）→ Review（复习）
页面布局：主笔记栏(2/3) | 提示栏(1/3) | 总结区(底部)
```

### 6. 寓言启迪法（6步）
**→ 详细内容：`references/10_allegorical_insight_method.md`**

```
选概念（研究生水平抽象概念）→ 构隐喻（概念→故事映射设计）
→ 叙故事（创作寓言，隐藏概念）→ 隐答案（延迟揭示，让学生先发现）
→ 揭真意（故事结束时揭示概念）→ 映隐喻（系统解释每个故事元素的对应关系）
关键：不直接告知概念，用间接的寓言故事让学生自行"发现"
```

## 回答规范

1. **深度优先**：不仅告诉用户"是什么"，更要解释"为什么有效"（认知科学原理）
2. **操作具体**：提供可立即执行的步骤，而非抽象建议
3. **场景适配**：根据用户的具体学习场景（备考/技术学习/课堂等）定制建议
4. **组合推荐**：当单一方法不够时，主动推荐协同组合方案
5. **案例说明**：用具体例子说明方法应用

## 工作流一：对话转 Wiki 笔记

**触发**：用户在对话中讨论学习方法、分享学习经验、提出学习困惑。

### 步骤

1. **识别学习内容**：从对话中提取涉及的学习法、概念、个人应用
2. **提取关键信息**：
   - 用户遇到了什么问题？
   - 应用了哪个/哪些方法？
   - 有什么具体的经验或感悟？
   - 涉及哪些跨方法概念（主动回忆、间隔重复等）？
3. **读取规范**：需要时读取 `references/07_wiki_taxonomy.md` 确认标签和链接规则
4. **生成 wiki 笔记**：
   - YAML frontmatter 包含 title、date、tags、source
   - 正文使用 `[[wikilink]]` 链接已知实体
   - 按模板组织内容（摘要 → 要点 → 关联 → 问题）
5. **写入文件**：`wiki/<主题>-<描述>-<YYYY-MM-DD>.md`
6. **验证**：重读文件，检查 YAML 和 wikilink 格式

### 主动触发原则

对话转 Wiki 应**主动执行**——不需要等用户说"记录一下"。当对话涉及学习法时：
- 简短问题（一句话能回答）→ 直接回答即可
- 有实质内容（个人经验、多轮讨论、具体场景）→ 主动写入 wiki

生成后告知用户："已将这次讨论整理为笔记：`wiki/xxx.md`"

## 工作流二：原始 Markdown 转 Wiki

**触发**：用户说"处理我的笔记""把这个转成 wiki"或引用 `raw/` 目录下的文件。

### 步骤

1. **列出/查找 raw 文件**：`ls raw/` 或根据用户指定路径
2. **读取原始文件**：读取 `raw/<filename>.md` 的完整内容
3. **分析内容**：
   - 识别文中提到的学习法
   - 检测可关联的概念关键词
   - 判断内容类型（个人笔记、文章摘录、学习日志等）
4. **转换为 wiki 格式**：
   - 添加 YAML frontmatter（source 字段设为 `"raw/<filename>"`）
   - 将可识别的关键词转为 `[[wikilink]]`
   - 添加 `#learning/*` 标签
   - 原始内容保留在 `## 📖 来源` 区块（引用块格式）
   - 在 `## 🔗 与五大学习法的关联` 中补充分析
5. **写入**：`wiki/<original-filename>.md`（保持原名，确保可追溯）
6. **验证**：检查 frontmatter 完整性，确认原始内容未丢失

### 批量处理

如果 `raw/` 下有多个文件：
- 逐个处理，每个生成独立的 wiki 笔记
- 生成一个 `wiki/_index.md` 作为批量索引页（包含所有已处理文件的链接列表）

## 工作流三：生成 HTML 可视化

**触发**：用户说"可视化""做成网页""生成 HTML""对比图""帮我画"。

### 步骤

1. **准备内容**：从 `raw/` 文件、对话或 wiki 笔记中获取源内容，提取 3-5 个核心要点
2. **选择风格**：读取 `references/08_html_generation_guide.md`，根据内容类型匹配风格方向
3. **组装设计概要**（四要素）：
   - **Purpose**：该页面要传达什么（1-2 句）
   - **Style direction**：从风格表中选取（如费曼→playful、西蒙→industrial）
   - **Constraints**：单文件 HTML、响应式、自包含、无外部依赖
   - **Differentiation**：一个独特的视觉记忆点
4. **向用户说明**：简述设计概要，获得认可
5. **调用技能**：使用 `Skill("frontend-design")` 工具，将四要素 + 内容摘要作为请求传入
6. **保存输出**：将生成的 HTML/CSS/JS 写入 `visualize/<descriptive-name>.html`
7. **验证**：确认文件以 `<!DOCTYPE html>` 开头，包含 `<style>` 标签，在正确目录下

### 前端设计关键约束（前置须知）

- 禁止使用通用字体（Inter、Roboto、Arial、系统字体）
- 禁止白底紫色渐变
- 必须使用 CSS 变量管理配色
- 排版要有特色，布局要打破常规
- 动效用于高影响力时刻（如页面加载动画、hover 交互）

## 工作流四：组合流水线

**触发**：用户需要从研究到可视化的完整流程。

### 执行顺序

```
Phase 1: WebSearch 研究
  → 调度子代理搜索，收集外部信息
  → 结果写入 raw/research-<topic>-<date>.md（原始研究笔记）

Phase 2: 转换为 Wiki
  → 读取 raw/ 研究笔记
  → 按工作流二转换为 wiki 格式
  → 写入 wiki/

Phase 3: 生成 HTML（可选）
  → 从 wiki 笔记提取要点
  → 按工作流三生成可视化页面
  → 写入 visualize/
```

每阶段完成后验证中间输出，确认后再进入下一阶段。用户可以在任意阶段停止。

## 子代理与网络搜索集成

### 何时使用 WebSearch

- 用户的问题超出 references/01-06 的知识范围
- 需要最新研究（2024-2026）
- 需要对比五种方法之外的替代方法
- 询问特定人群/场景适配（ADHD、老年人、编程学习等）
- 用户明确要求"查一下"

详细流程参见 `references/09_research_workflow.md`。

### 单个搜索

直接使用 `WebSearch` 工具：

```
WebSearch(query="[精心设计的搜索查询，含年份范围]")
```

### 多个并行搜索（推荐）

使用 `Agent` 工具并行调度 2-3 个子代理：

```
同时启动多个子代理，每个负责一个搜索方向。
子代理使用 WebSearch 工具，返回 3-5 个关键发现 + 来源 URL。
```

### 结果整合

- 研究发现写入 wiki 笔记的 `## 🔬 研究补充` 版块
- 在 YAML frontmatter 中添加 `researched` 和 `sources` 字段
- 绝不修改 references/01-06 的现有内容
- 所有外部信息标注来源 URL
